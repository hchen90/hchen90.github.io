16:Tf41,<p>SQL Server is Microsoft's database product and a fairly well-known one. SQL Server 2000 was especially popular with users and widely recognized, and SQL Server 2008 is one of its successors. Let's get straight to it (this post does not cover installing VS or SQL Server; it assumes the environment is already set up).</p>
<p>First, go to <code>View</code> -> <code>Other Windows</code> -> <code>Server Explorer</code> in the menu. This opens a small floating window that looks like this:</p>
<p><img src="/post/vssqlserver2008/524a2775c659.png" alt="Server Explorer window"></p>
<p>Right-click the <code>Data Connections</code> node and choose <code>Create New SQL Server Database</code>. The following dialog appears:</p>
<p><img src="/post/vssqlserver2008/0493365c3b52.png" alt="Create New SQL Server Database dialog"></p>
<p>Click <code>Refresh</code>, then pick a server from the drop-down on the left. If none shows up, the local server side has not been started (assuming your machine is offline). Large, highly stable databases like this usually have a server process that listens for connections and applies data changes internally. In effect, the database's logical schema and internal schema live on the server side (much like an Apache server doing its work on the server).</p>
<p>If the server is not running, start the service. This is the same idea as running <code>service mysqld start</code> for MySQL on Linux. On Windows, find <code>Services</code> in the Start menu (on Win7 it is under <code>Administrative Tools</code>), or type <code>services.msc</code> at the command line. In the <code>Services</code> window, find <code>SQL Server (SQLEXPRESS)</code>,</p>
<p><code>SQL Server Browser</code>, and <code>SQL Server VSS Writer</code>, and start them. Go back to the dialog above, click <code>Refresh</code>, and open the drop-down again: you should now see the server name, which means the server side is up and ready for connections.</p>
<p>After selecting the server above, enter a name for the new database and click <code>OK</code> to create it.
Once the database is created, connect to it.</p>
<p>Again, right-click the <code>Data Connections</code> node and choose <code>Add Connection</code>. A <code>Choose Data Source</code> dialog appears:</p>
<p><img src="/post/vssqlserver2008/0f72499c920a.png" alt="Choose Data Source dialog"></p>
<p>Select <code>Microsoft SQL Server</code> and click <code>Continue</code>. An <code>Add Connection</code> dialog then appears:</p>
<p><img src="/post/vssqlserver2008/ae0268d55a7b.png" alt="Add Connection dialog"></p>
<p>The server name is the one that became available after starting the service; you can see it in the drop-down. For the database name, enter the database you just created, or pick your database from the drop-down. Before confirming, you can click <code>Test Connection</code> to verify it, then click <code>OK</code>.</p>
<p>Actually, you don't need to create a new database before choosing a database name in <code>Add Connection</code>. In the <code>Add Connection</code> dialog, just pick any other database for the database name field and log in to the database system. Once logged in, run <code>create database XXX;</code> in the query pane to create a database, where XXX is the database name. To delete/destroy it, run <code>drop database XXX;</code> to drop the XXX database.</p>
<p>In <code>Server Explorer</code>, you can see the new database listed under <code>Data Connections</code>:</p>
<p><img src="/post/vssqlserver2008/26d073fc8ae4.png" alt="New database under Data Connections"></p>
<p>Under <code>Data Connections</code> in the explorer, right-click the database. The context menu has many entries; choose <code>New Query</code> and you can operate on the database using SQL.</p>
