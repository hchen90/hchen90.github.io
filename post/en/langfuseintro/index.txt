16:T4f6e,<p>After an LLM app ships, developers quickly learn that a single user request often passes through prompt assembly, multiple model calls, RAG retrieval, tool use, and Agent decisions. When something goes wrong, you only see a bad final answer and struggle to tell which step drifted. Langfuse is an open-source observability platform built for that kind of black-box problem.</p>
<h2 id="what-is-langfuse">What is Langfuse<a aria-hidden="true" tabindex="-1" href="#what-is-langfuse"><span class="anchor-link"> #</span></a></h2>
<p><strong>Langfuse</strong> is an open-source LLM engineering / LLMOps observability platform for building, monitoring, debugging, and improving large-language-model apps and AI agents. It centers on <strong>Tracing</strong>: every model call, tool run, retrieval result, and state change inside a request is recorded as a structured Trace so teams can debug LLM pipelines the way they debug traditional microservices.</p>
<p>Compared with <strong>LangSmith</strong>, which also targets LLM observability, Langfuse’s biggest difference is <strong>open source and self-hosting</strong>. LangSmith is a closed-source SaaS product from the LangChain team—capable, but usage-based past the free tier, and not fully deployable in a private environment. Langfuse is fully open under the <strong>MIT license</strong>, auditable in the open; you can use hosted <strong>Langfuse Cloud</strong> or self-host for free on your own infrastructure, with full control over data and cost.</p>
<p>You can use the project in two ways:</p>
<ul>
<li><strong>Langfuse Cloud</strong>: Official hosted SaaS, good for a quick start or small teams.</li>
<li><strong>Self-Hosted</strong>: Private deploy with Docker Compose or Kubernetes, no Langfuse license fee, data stays on your infrastructure.</li>
</ul>
<p>Whether you call OpenAI / Anthropic / local models directly or go through LangChain, LlamaIndex, OpenTelemetry, and similar stacks, Langfuse can capture the important telemetry with relatively low instrumentation cost.</p>
<h2 id="core-features">Core features<a aria-hidden="true" tabindex="-1" href="#core-features"><span class="anchor-link"> #</span></a></h2>
<p>Langfuse’s capabilities follow three themes—observe, evaluate, iterate. The main modules are below.</p>
<h3 id="tracing">Tracing<a aria-hidden="true" tabindex="-1" href="#tracing"><span class="anchor-link"> #</span></a></h3>
<p>Tracing is the foundation. Each user request maps to one <strong>Trace</strong>, broken along a timeline into <strong>Spans</strong> and <strong>Generations</strong>:</p>
<ul>
<li><strong>Generation</strong>: One LLM call—prompt input, model parameters, output, token usage, and latency.</li>
<li><strong>Span</strong>: Any business step, such as RAG retrieval, tool calls, or knowledge-base queries.</li>
<li><strong>Event</strong>: Notable events such as user feedback or errors.</li>
</ul>
<p>Nested structure makes latency, cost, and intermediate state visible at each stage, so you can find hallucinations, timeouts, or retrieval failures faster.</p>
<p><img src="/post/langfuseintro/ce00805a6ef8.png" alt="tracing"></p>
<h3 id="metrics">Metrics<a aria-hidden="true" tabindex="-1" href="#metrics"><span class="anchor-link"> #</span></a></h3>
<p>The platform aggregates Trace data into observability metrics:</p>
<ul>
<li>Token usage and estimated cost</li>
<li>Latency distributions (P50 / P95 / P99)</li>
<li>Error rate and success rate</li>
<li>Model usage distribution</li>
</ul>
<p>You can view them in the Dashboard or export via API into Prometheus / Grafana or your BI stack.</p>
<p><img src="/post/langfuseintro/4f687f15edd8.png" alt="metrics"></p>
<p><img src="/post/langfuseintro/60d120180cea.png" alt="metrics_p"></p>
<h3 id="evals">Evals<a aria-hidden="true" tabindex="-1" href="#evals"><span class="anchor-link"> #</span></a></h3>
<p>Langfuse splits evaluation into two modes:</p>
<ul>
<li><strong>Online</strong>: After production traffic arrives, score automatically with rules, LLM-as-a-judge, or custom functions, and attach scores to concrete Traces.</li>
<li><strong>Offline</strong>: Run batch evaluations on datasets for regression tests, A/B comparisons, and prompt-version comparisons.</li>
</ul>
<p>Results land as <strong>Scores</strong> on Traces or Generations so teams can quantify model quality and track trends.</p>
<p><img src="/post/langfuseintro/09e328649a1f.png" alt="evals_1"></p>
<p><img src="/post/langfuseintro/a458f23e4ff4.png" alt="evals_2"></p>
<p><img src="/post/langfuseintro/e0de38f9497f.png" alt="evals_3"></p>
<h3 id="prompt-management">Prompt Management<a aria-hidden="true" tabindex="-1" href="#prompt-management"><span class="anchor-link"> #</span></a></h3>
<p>Langfuse provides versioned prompt management:</p>
<ul>
<li>Create, edit, and version prompt templates in the UI.</li>
<li>Call them in code by <code>prompt_name</code> and <code>version</code> so prompts are not scattered across the codebase.</li>
<li>Prompt changes can link directly to Traces, so you can see how version changes affect outputs.</li>
</ul>
<h3 id="datasets">Datasets<a aria-hidden="true" tabindex="-1" href="#datasets"><span class="anchor-link"> #</span></a></h3>
<p>Datasets are for test sets and benchmarks:</p>
<ul>
<li>Promote bad cases from production Traces into a dataset in one click.</li>
<li>Replay the same inputs to compare models or prompt versions.</li>
<li>Wire into CI for automatic regression before prompt or model changes ship.</li>
</ul>
<p><img src="/post/langfuseintro/3a920a4b821c.png" alt="datasets"></p>
<h2 id="install-and-deploy">Install and deploy<a aria-hidden="true" tabindex="-1" href="#install-and-deploy"><span class="anchor-link"> #</span></a></h2>
<p>Self-hosting Langfuse is Docker-first. Below is the core idea for a local trial and production; for exact image tags and the full variable list, prefer the <a href="https://langfuse.com/docs/deployment/self-host">official self-host docs</a>.</p>
<h3 id="local-quick-start">Local quick start<a aria-hidden="true" tabindex="-1" href="#local-quick-start"><span class="anchor-link"> #</span></a></h3>
<p>The official recommendation is Docker Compose. A minimal local stack usually includes:</p>
<ul>
<li><code>langfuse-web</code>: Web UI and API entrypoint.</li>
<li><code>langfuse-worker</code>: Background jobs (batch writes, evaluation tasks, and so on).</li>
<li><code>postgres</code>: Metadata and project data.</li>
<li><code>clickhouse</code>: Trace and event storage.</li>
<li><code>redis</code>: Job queue and cache.</li>
<li><code>minio</code>: S3-compatible object storage (uploads, images, and similar).</li>
</ul>
<p>Prepare a <code>.env</code> file:</p>

<h3 id="production-notes">Production notes<a aria-hidden="true" tabindex="-1" href="#production-notes"><span class="anchor-link"> #</span></a></h3>
<p>When moving from a local trial to production, pay attention to:</p>
<ul>
<li><strong>External DB and object storage</strong>: Use managed PostgreSQL, Redis, and S3; avoid keeping state only inside containers.</li>
<li><strong>Persistence and backups</strong>: ClickHouse and PostgreSQL need regular backups—Trace volume grows quickly.</li>
<li><strong>High availability</strong>: Scale <code>langfuse-web</code> and <code>langfuse-worker</code> horizontally; HA for DB and object storage is separate.</li>
<li><strong>Security</strong>:
<ul>
<li>Manage encryption secrets (<code>NEXTAUTH_SECRET</code>, <code>SALT</code>, <code>ENCRYPTION_KEY</code>) via a secrets store; do not commit them to Git.</li>
<li>Put HTTPS and appropriate access control in front of the web service.</li>
</ul>
</li>
<li><strong>Capacity planning</strong>: Trace volume scales with traffic; size ClickHouse and object storage against your retention policy.</li>
</ul>
<p>If the team is not ready to operate Kubernetes, Langfuse Cloud is the lower-ops option: same product surface, infrastructure hosted by the vendor.</p>
<h2 id="basic-usage">Basic usage<a aria-hidden="true" tabindex="-1" href="#basic-usage"><span class="anchor-link"> #</span></a></h2>

<h3 id="view-in-the-dashboard">View in the Dashboard<a aria-hidden="true" tabindex="-1" href="#view-in-the-dashboard"><span class="anchor-link"> #</span></a></h3>
<p>After running the code, open the Langfuse web UI for that project. You should see:</p>
<ul>
<li><strong>Traces</strong>: Requests on a timeline; open one for the full call chain.</li>
<li><strong>Generations</strong>: All LLM calls, filterable by model, latency, and cost.</li>
<li><strong>Scores</strong>: Manual or automatic scores on Traces to track quality trends.</li>
<li><strong>Dashboards</strong>: Aggregated token use, latency, error rate, and more.</li>
</ul>
<p>From a Trace you can drill into a Generation and inspect the prompt, model parameters, and raw output to find the root cause faster.</p>
<h2 id="summary">Summary<a aria-hidden="true" tabindex="-1" href="#summary"><span class="anchor-link"> #</span></a></h2>
<h3 id="good-fit-for">Good fit for<a aria-hidden="true" tabindex="-1" href="#good-fit-for"><span class="anchor-link"> #</span></a></h3>
<p>Langfuse works especially well for:</p>
<ul>
<li><strong>RAG apps</strong>: You need to connect retrieval, re-ranking, context assembly, and final generation.</li>
<li><strong>Agent systems</strong>: Agents call models, tools, and external APIs many times; Traces show each decision and state change.</li>
<li><strong>Multi-model strategies</strong>: When you call several models or fall back between them, you need latency, cost, and quality side by side.</li>
<li><strong>Cost-sensitive products</strong>: Track tokens per user or session and spot abnormal or expensive traffic.</li>
<li><strong>Teams that iterate continuously</strong>: Tie prompt versions, eval scores, and production feedback into one loop.</li>
</ul>
<h3 id="how-it-differs-from-similar-tools">How it differs from similar tools<a aria-hidden="true" tabindex="-1" href="#how-it-differs-from-similar-tools"><span class="anchor-link"> #</span></a></h3>
<p>There are many LLM observability tools—LangSmith, Phoenix (Arize), Weights &#x26; Biases, and others. Langfuse stands out mainly because:</p>
<ul>
<li><strong>Open source and self-hostable</strong>: MIT license, Docker and Kubernetes self-hosting, full data ownership.</li>
<li><strong>Tracing-first</strong>: Clear Trace structure with Generation / Span / Event layers for drill-down debugging.</li>
<li><strong>One platform</strong>: Observability (Tracing/Metrics), evaluation (Evals), prompt management, and datasets in one place, less tool sprawl.</li>
<li><strong>Framework-agnostic</strong>: Official SDKs plus OpenTelemetry, LangChain, LlamaIndex, Vercel AI SDK, and more.</li>
</ul>
<h3 id="getting-started">Getting started<a aria-hidden="true" tabindex="-1" href="#getting-started"><span class="anchor-link"> #</span></a></h3>
<p>For teams new to Langfuse, a practical order is:</p>
<ol>
<li><strong>Validate on Cloud first</strong>: Sign up for Langfuse Cloud, spend ~30 minutes wiring a real endpoint, and confirm Traces look right.</li>
<li><strong>Cover critical paths</strong>: Add the SDK or decorator on core production calls so you can see what matters first.</li>
<li><strong>Add metadata</strong>: Put <code>user_id</code>, <code>session_id</code>, and <code>metadata</code> on Traces for later aggregation by user or session.</li>
<li><strong>Introduce evals</strong>: Start with simple rule scores or LLM-as-a-judge and build a quality baseline.</li>
<li><strong>Version prompts</strong>: Move critical prompts into Langfuse Prompt Management and link them to Traces.</li>
<li><strong>Self-host when needed</strong>: Move to Self-Hosted when compliance, cost, or customization requirements are clear.</li>
</ol>
