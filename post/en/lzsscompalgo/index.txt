16:T3c0e,<h1 id="introduction-to-lzss">Introduction to LZSS<a aria-hidden="true" tabindex="-1" href="#introduction-to-lzss"><span class="anchor-link"> #</span></a></h1>
<p>LZSS is an improved version of LZ77, published by James A. Storer and Thomas Szymanski in the Journal of the ACM in 1982. LZSS makes full use of bit flags, which significantly improves compression efficiency compared with LZ77.</p>
<blockquote>
<p>See Wikipedia: <a href="https://en.wikipedia.org/wiki/Lempel%E2%80%93Ziv%E2%80%93Storer%E2%80%93Szymanski">lzss</a></p>
</blockquote>
<h1 id="how-the-algorithm-works">How the algorithm works<a aria-hidden="true" tabindex="-1" href="#how-the-algorithm-works"><span class="anchor-link"> #</span></a></h1>
<p>Before reading this post, you should know the general flow of LZ77; if not, read <a href="/post/en/lz77compalgo">this post</a> first.</p>
<p>LZSS and LZ77 share the same encoding/decoding logic; the difference lies in how encoded data is marked. Below I describe LZSS's marking scheme in detail, which shows how it improves compression efficiency so much.</p>
<p>A key concept in LZSS encoding is: grouping data.</p>
<p>A byte consists of 8 bits, so one byte can flag whether each of the following (at least) 8 items is a compressed code, instead of using a <code>\0x00\0x00</code> prefix to distinguish compressed from uncompressed data. This saves the large overhead of all those <code>\0x00\0x00</code> prefixes.</p>
<p>How the grouping flags work:</p>
<p><img src="/post/lzsscompalgo/9c651b397128.png" alt="Data grouping flag bits"></p>
<blockquote>
<p>As you can see, with this grouping scheme the worst case adds only one extra byte for every 8 bytes, a big improvement over the 2 extra bytes per literal byte in LZ77.</p>
</blockquote>
