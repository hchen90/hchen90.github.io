<h2 id="mediator">Mediator<a aria-hidden="true" tabindex="-1" href="#mediator"><span class="anchor-link"> #</span></a></h2>
<p>The Mediator pattern reduces chaotic, tangled dependencies between objects. It restricts direct interaction between objects and has them interact through a mediator object instead.</p>
<p>Consider a form UI where the user fills in name, date of birth, gender, and so on. Updating one field also triggers changes in other UI elements; for example, entering a date of birth updates the age in the form. If every UI control talked to the others directly to update them, the result would eventually be a mess. A mediator prevents that mess.</p>
<p><img src="/post/softwaredesignpattern4/1decbdf92c84.png" alt="Mediator"></p>
<p>As shown above, changing the date of birth updates the age, and routing this through the mediator avoids the chaos caused by direct calls.</p>

<blockquote>
<p>How state machines work</p>
<blockquote>
<p>A state machine consists of a symbol table, a state table, a transition function, and start and end states. In one sentence: a state machine uses symbols from the symbol table to move between states in the state table via the transition function. State machines are divided into finite and infinite state machines; an infinite state machine's state table differs in size from a finite one's and may contain infinitely many states. Finite state machines are used in compilers, both for lexical analysis and for building formal syntax analysis.</p>
</blockquote>
