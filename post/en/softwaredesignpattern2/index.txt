<h2 id="factory-method">Factory Method<a aria-hidden="true" tabindex="-1" href="#factory-method"><span class="anchor-link"> #</span></a></h2>
<p>The Factory Method pattern is <strong>a way of declaring a method in the parent class and instantiating the object in a subclass</strong>. In C++ it is usually expressed with virtual functions; in other languages such as Java, with abstract methods.</p>
<p>The Factory Method pattern focuses on the target "product" itself, and generally uses a common interface to instantiate an object's properties.</p>
<p>Take a graphics-drawing application as an example. For the parent class we only care about the high-level requirement (drawing a shape); here that corresponds to a graphic. The structure is as follows:</p>

<h2 id="abstract-factory">Abstract Factory<a aria-hidden="true" tabindex="-1" href="#abstract-factory"><span class="anchor-link"> #</span></a></h2>

<h2 id="builder">Builder<a aria-hidden="true" tabindex="-1" href="#builder"><span class="anchor-link"> #</span></a></h2>

<p>With a builder, you call various interfaces one after another to perform specific initialization and set the object's properties. Once initialization is done, you call a build function (<code>build()</code>) to produce the target object.</p>

<h2 id="prototype">Prototype<a aria-hidden="true" tabindex="-1" href="#prototype"><span class="anchor-link"> #</span></a></h2>

<h2 id="singleton">Singleton<a aria-hidden="true" tabindex="-1" href="#singleton"><span class="anchor-link"> #</span></a></h2>
<p>A singleton is a special construction pattern: the object it constructs has only one global instance at runtime.</p>
<p>Singletons are typically used for central control and centralized configuration, ensuring consistency of information and of control.</p>
