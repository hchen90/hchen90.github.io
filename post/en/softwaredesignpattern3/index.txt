16:T83e8,<p>Structural patterns describe how classes and objects are assembled into larger structures while keeping those structures flexible and efficient.</p>
<p>The structural patterns covered here are: Adapter, Bridge, Composite, Decorator, Facade, Flyweight, and Proxy.</p>
<h2 id="adapter">Adapter<a aria-hidden="true" tabindex="-1" href="#adapter"><span class="anchor-link"> #</span></a></h2>
<p>The Adapter pattern solves the problem of making incompatible interfaces work together.</p>
<p>Adapters usually come in two flavors: object adapters and class adapters.</p>

<h2 id="flyweight">Flyweight<a aria-hidden="true" tabindex="-1" href="#flyweight"><span class="anchor-link"> #</span></a></h2>
<p>The Flyweight pattern shares object state so that each object does not have to hold all of its state, which lets you fit many more objects into memory.</p>
<p>A typical use case is game development. One of the most common elements in a game is the particle system, where each particle has its own coordinates, color, state, and so on. If every particle object stored all of that information, a real game scene would demand an enormous amount of memory: a few hundred thousand particles could exhaust system memory and trigger an OOM. To solve this, analyze the particle class, separate its constant parts from its variable parts, and store the constant parts in shared objects.</p>
<p>As shown below:</p>

<h2 id="proxy">Proxy<a aria-hidden="true" tabindex="-1" href="#proxy"><span class="anchor-link"> #</span></a></h2>
<p>The Proxy pattern provides a placeholder for an object and controls access to the original object, so extra processing can be added before and after external requests reach it.</p>
<p>Sticking with the drawing example: this time we draw images, which are stored in a database with a tag as each image's unique name. Every draw has to fetch the corresponding images from the database before drawing them. When a figure is complex and contains many images, drawing becomes slow and the UI visibly lags. The root cause is the accumulated time spent fetching images from the database. The Proxy pattern addresses this, as shown below:</p>
<p><img src="/post/softwaredesignpattern3/68bf559f3059.png" alt="Proxy"></p>
<p>When the proxy fetches an image, it caches it. The next time the same image is requested, the proxy returns it immediately, which greatly cuts drawing time and makes drawing more efficient.</p>
