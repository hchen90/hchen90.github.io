16:T225a,<h2 id="about-tex">About TeX<a aria-hidden="true" tabindex="-1" href="#about-tex"><span class="anchor-link"> #</span></a></h2>
<p><strong>TeX</strong> is a computer typesetting system originally created by Donald E. Knuth, professor at Stanford University. Most of you will know him from <em>The Art of Computer Programming</em>.</p>
<p>In fact, TeX was born because Knuth was unhappy with the proofs of that very book, which pushed him to build his own typesetting system. As the saying goes, one concrete need sets the direction better than ten universities.</p>
<p>You probably do everyday typesetting with WYSIWYG tools such as MS Word, or LibreOffice Writer on Linux. But for papers and books, those tools are child's play compared with TeX.</p>
<p>Enough background—today's topic is setting up TeX on Linux, so I'll get straight to it. If anything is unclear, search it yourself.</p>
<p>First, prepare the following packages or archives:</p>
<ul>
<li>texlive or tetex</li>
<li>CJK</li>
<li>Fonts, for example nsung-tl and nkai-tl <em>(the trailing "tl" presumably stands for texlive)</em></li>
</ul>
<p>Below is a brief introduction to what each one does.</p>
<h3 id="1-texlive-or-tetex">1. texlive or tetex<a aria-hidden="true" tabindex="-1" href="#1-texlive-or-tetex"><span class="anchor-link"> #</span></a></h3>
<p>This package is the main part of the whole typesetting system—its core. texlive and tetex are two distributions with essentially the same functionality; you only need one of them. The rest of this post uses texlive as the example, though many other software packages also implement a TeX system.</p>
<p>With texlive alone, TeX can in theory already typeset documents, but it only provides primitive commands. Using it directly is tedious and requires a lot more code. It is similar to writing a GUI program in plain C versus with MFC on Windows, or on Linux, writing a GUI in plain C against the Xlib X Window API versus using gtk+ or Qt (in C++).</p>
<p>Like TeX, LaTeX is a component of texlive. LaTeX's signature feature is automatic numbering—of chapters, sections, paragraphs, equations, figures, and tables—which makes typesetting far more convenient.</p>
<h3 id="2-cjk">2. CJK<a aria-hidden="true" tabindex="-1" href="#2-cjk"><span class="anchor-link"> #</span></a></h3>
<p>The original LaTeX does not support Chinese; it only supports English, i.e. ASCII characters below 0x80. To make LaTeX handle Chinese, you need to add macros to the LaTeX system. CJK handles not only Chinese but also Japanese and Korean—CJK stands for Chinese, Japanese, Korean.</p>
<h3 id="3-fonts">3. Fonts<a aria-hidden="true" tabindex="-1" href="#3-fonts"><span class="anchor-link"> #</span></a></h3>
<p>Installing the CJK macro package alone still won't let you output Chinese (compiling a .tex file will fail with a missing-font error). Punctuation in these fonts is treated as part of the Chinese font, so it does not affect how Chinese punctuation is rendered. Like the macro package, the fonts come as archives.</p>
<h2 id="step-by-step-installation">Step-by-step installation<a aria-hidden="true" tabindex="-1" href="#step-by-step-installation"><span class="anchor-link"> #</span></a></h2>
<p>Once everything above is downloaded, first install texlive so the system has a basic TeX environment. If this is your first texlive install, you need to install the install-tl-unx package beforehand; it contains Perl scripts that set up the prerequisites for installing texlive.</p>
<p>With the base TeX environment in place, LaTeX—which we definitely need—comes with it. You can think of LaTeX as an extension of TeX that makes the system much simpler and more convenient to use.</p>
<p>After texlive is installed, install the CJK macro package. It is an archive: extract it, then follow its texmf-relative directory layout and copy each file into the corresponding location under your system's texmf directory. This texmf directory may differ between Linux distributions: mine is <code>/usr/share/texmf</code>, some systems use <code>/opt/texlive/texmf</code>, and others even <code>/usr/local/share/texmf</code>.</p>
<p>After copying the CJK macros, run texhash to refresh the index so the TeX system can find the newly copied packages. <em>(When you run texhash, the CJK directories and files are added to the ls-R index file.)</em></p>
<p>You're almost done at this point. But without fonts you still can't output Chinese. Font installation differs from the packages above: fonts are installed directly into the user's home directory, e.g. <code>/home/xxx</code>. Afterwards a texmf folder appears in your home directory containing the font data—don't delete it, or the fonts will be gone again.</p>
<p>Here is the font installation in more detail. Extract the font archive, <code>cd</code> into the extracted directory in a terminal, and <code>ls</code> will show an <code>install.sh</code> and an <code>uninstall.sh</code>.</p>
<p>To install the font, just run:</p>
<div class="code-block-wrapper"><div class="code-block-header"><span class="code-block-lang">bash</span><button class="copy-button" data-copy-state="copy" aria-label="Copy code to clipboard" type="button" onclick="copyCode(this)"><span class="copy-button-text">Copy</span></button></div><pre><code class="hljs language-bash">./install.sh
</code></pre></div>
<p>When you no longer want the font, just run:</p>
<div class="code-block-wrapper"><div class="code-block-header"><span class="code-block-lang">bash</span><button class="copy-button" data-copy-state="copy" aria-label="Copy code to clipboard" type="button" onclick="copyCode(this)"><span class="copy-button-text">Copy</span></button></div><pre><code class="hljs language-bash">./uninstall.sh
</code></pre></div>
<p>These fonts are installed into the user's <code>texmf</code> directory, so there's no need to switch to root, and the installed fonts only apply to that user.</p>
<blockquote>
<p>I didn't go into detail about installing the software above; those are routine steps and are skipped here. For example, install rpm packages with rpm and resolve dependencies; for source builds, run <code>./configure</code> to generate a Makefile, then <code>make</code>, then <code>make install</code>. Some have many options—check <code>./configure --help</code>. Those two make commands are the most basic; others such as <code>make dist/test/pdf/...</code> <em>(you can actually look them up in the Makefile)</em> are things non-specialists can safely ignore.</p>
</blockquote>
