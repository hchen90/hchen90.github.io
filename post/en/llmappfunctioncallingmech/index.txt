16:T6cd5,<p>LLMs are used very widely today, from the most common chat Q&#x26;A (e.g. ChatGPT, DeepSeek chat) to retrieval-based question answering systems; you see them everywhere.</p>
<p>In LLM (large language model) application development, <strong>Function Calling</strong> is a powerful mechanism that lets a model go beyond pure text generation and interact with the outside world more deeply. Through it, we can give an LLM the ability to invoke specific tools or APIs, unlocking countless complex and practical use cases.</p>
<h2 id="what-is-function-calling">What is Function Calling<a aria-hidden="true" tabindex="-1" href="#what-is-function-calling"><span class="anchor-link"> #</span></a></h2>
<p>Simply put, Function Calling is the ability for an LLM to understand and generate specific structured data (JSON) that triggers an external function or tool. You don't have the model perform an operation directly; instead you tell it, "when the user wants to do X, return a function name with specific arguments to me." Your application code then receives this "function call" instruction and is responsible for actually executing the function.</p>
<p>By definition, Function Calling is the model generating structured data to trigger an external function.</p>
<p>The overall workflow is:</p>
<ol>
<li>The developer provides function descriptions (schemas) to the LLM.</li>
<li>The user's input creates a need for one of the functions.</li>
<li>The LLM generates a JSON object containing the function name and arguments, based on the function description.</li>
<li>The developer's application code parses and executes the function.</li>
</ol>
<h2 id="why-function-calling-is-needed">Why Function Calling is needed<a aria-hidden="true" tabindex="-1" href="#why-function-calling-is-needed"><span class="anchor-link"> #</span></a></h2>
<p>Without Function Calling, an LLM can only answer with what it already "knows". Ask "What's the weather like today?" and it may produce a description of weather, but it can't actually tell you the current conditions.</p>
<h3 id="limitations-of-llms">Limitations of LLMs<a aria-hidden="true" tabindex="-1" href="#limitations-of-llms"><span class="anchor-link"> #</span></a></h3>
<p>Function Calling addresses several limitations of LLMs.</p>
<h4 id="a-static-knowledge-base">A static knowledge base<a aria-hidden="true" tabindex="-1" href="#a-static-knowledge-base"><span class="anchor-link"> #</span></a></h4>
<p>An LLM is trained on a huge body of knowledge, but that knowledge is static: it cannot get the current weather in Shanghai.</p>
<h4 id="limited-model-capabilities">Limited model capabilities<a aria-hidden="true" tabindex="-1" href="#limited-model-capabilities"><span class="anchor-link"> #</span></a></h4>
<p>Continuing the example above: if we want to save the weather we retrieved, the LLM cannot store it in a database for later analysis on our behalf.</p>
<h4 id="limited-reliability-of-model-output">Limited reliability of model output<a aria-hidden="true" tabindex="-1" href="#limited-reliability-of-model-output"><span class="anchor-link"> #</span></a></h4>
<p>LLMs have always had the "hallucination" problem. Without grounding in a specific context, their answers may be inaccurate; for example, if you ask one to guess how to use an API without giving it the exact format, what it produces may well be wrong.</p>
<h2 id="building-a-simple-function-calling-application">Building a simple Function Calling application<a aria-hidden="true" tabindex="-1" href="#building-a-simple-function-calling-application"><span class="anchor-link"> #</span></a></h2>
<p>To demonstrate a Function Calling application, I chose OpenRouter as the LLM cloud provider. It integrates a large number of LLM vendors, which makes choosing a model convenient.</p>
<p>One thing to note: OpenRouter offers many models, many of them free. If you want to use Function Calling, whether the model is free or paid, first check whether it supports Function Calling; you can use the filter on the left side of the page (filter by Tools support).</p>
<p><img src="/post/llmappfunctioncallingmech/1c3a72fe6c9d.png" alt="Filtering OpenRouter models that support tools"></p>

<h3 id="chaining">Chaining<a aria-hidden="true" tabindex="-1" href="#chaining"><span class="anchor-link"> #</span></a></h3>
<p>Chaining is a popular style. It abstracts each conversation with the LLM into a session transaction, where each transaction handles one step of solving a problem (this eases the LLM's token limit and matches a problem-decomposition mindset). Linking these steps into a chain gives you a solution to a complex problem.</p>
<blockquote>
<p>LangChain</p>
<p>LangChain is an open-source framework designed specifically to implement and manage "chains". It provides a full toolkit for this and is very easy to get started with.</p>
</blockquote>
<p>As an example of chaining, consider a novel-summarization system. Traditionally, with a single LLM session, a whole novel obviously can't fit, so we decompose the problem, for instance by defining some external functions:</p>
<ul>
<li>List the chapters</li>
<li>Measure each chapter's size and summarize it in segments</li>
<li>Combine the chapter summaries</li>
<li>Summarize the whole novel</li>
</ul>
<p>The flow looks like this:
<img src="/post/llmappfunctioncallingmech/ebd0ff9ba8e7.png" alt="LangChain summarization flow"></p>
<blockquote>
<p>Improving on LangChain</p>
<p>The problem with LangChain is that it is sequential, which inevitably leads to overly long chains for complex problems. This led to LangGraph, whose main feature is running things that can be parallelized in parallel, so answers come back faster, at the cost of added system complexity.</p>
</blockquote>
