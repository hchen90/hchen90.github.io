16:T1c94,<h2 id="background">Background<a aria-hidden="true" tabindex="-1" href="#background"><span class="anchor-link"> #</span></a></h2>
<p>Reading MINIX source code directly inside the virtual machine is very inconvenient, and modifying, debugging, or porting it there is even harder. If you copy part of the MINIX source to the host Linux machine, editing and debugging become much easier.</p>
<p>However, MINIX is a fairly bare-bones system. You can't simply install VMware Tools as you would for a Windows guest in VMware (it lacks X Window; in theory you could install X on MINIX, but that's a lot of hassle and overkill just for a few source files). VMware's disk files (<code>.vmdk</code>) are not raw disk images, and VMware doesn't recognize the file systems of niche systems like MINIX very well. As a result, you can't mount the MINIX disk on the host with VMware, so you still can't get the files out of the MINIX guest.</p>
<p>So I chose QEMU instead. QEMU disks are raw data files that can be mounted directly into the Linux file tree (as long as Linux recognizes the file system).</p>
<h2 id="software-and-systems">Software and Systems<a aria-hidden="true" tabindex="-1" href="#software-and-systems"><span class="anchor-link"> #</span></a></h2>
<ul>
<li>MINIX: <code>minix_R3.2.0-116fcea.iso</code></li>
<li>QEMU: <code>qemu-system-i386</code></li>
</ul>
<h2 id="steps">Steps<a aria-hidden="true" tabindex="-1" href="#steps"><span class="anchor-link"> #</span></a></h2>
<p>Download the MINIX ISO, start QEMU on Linux, and install MINIX with:</p>
<div class="code-block-wrapper"><div class="code-block-header"><span class="code-block-lang">bash</span><button class="copy-button" data-copy-state="copy" aria-label="Copy code to clipboard" type="button" onclick="copyCode(this)"><span class="copy-button-text">Copy</span></button></div><pre><code class="hljs language-bash">qemu-system-i386 -enable-kvm -sdl -cdrom minix_R3.2.0-116fcea.iso -hda minix.img
</code></pre></div>
<blockquote>
<p>If you don't have the minix.img disk image yet, create it with <code>qemu-img create minix.img 2G</code> or <code>touch minix.img &#x26;&#x26; truncate minix.img --size=2G</code>.</p>
</blockquote>
<p>After MINIX is installed, prepare a spare virtual disk image, say <code>a.img</code>. This disk will hold the source files you need. Once the image is created, don't rush to partition or format it on Linux; that should be done inside the MINIX guest.</p>
<p>With both <code>minix.img</code> and <code>a.img</code> ready, boot the VM again to copy files:</p>
<div class="code-block-wrapper"><div class="code-block-header"><span class="code-block-lang">bash</span><button class="copy-button" data-copy-state="copy" aria-label="Copy code to clipboard" type="button" onclick="copyCode(this)"><span class="copy-button-text">Copy</span></button></div><pre><code class="hljs language-bash">qemu-system-i386 -enable-kvm -sdl -hda minix.img -hdb a.img
</code></pre></div>
<blockquote>
<p>Here <code>minix.img</code> already has MINIX installed from the previous step.</p>
</blockquote>
<p>Once the QEMU VM is up, log in to MINIX as <code>root</code>. MINIX organizes devices differently from Linux: disks are usually named like <code>c0d0p0</code>, where the first <code>c</code> stands for "Controller", the digit is an index, <code>d</code> stands for "Disk", <code>p</code> stands for "Partition", and there is also <code>s</code> for "Subpartition". Run <code>man dev</code> for a detailed explanation.</p>
<p>Use <code>df</code> to figure out which disk <code>minix.img</code> occupies. At this point, <code>a.img</code> is attached to MINIX, but we don't yet know which device it is. First rule out the disk used by <code>minix.img</code>, say <code>c0d0</code>; mounting an already-mounted disk with <code>mount</code> will just report it as busy. The CD-ROM is usually <code>c0d2</code>. Try mounting <code>c0d1</code>:</p>
<div class="code-block-wrapper"><div class="code-block-header"><span class="code-block-lang">bash</span><button class="copy-button" data-copy-state="copy" aria-label="Copy code to clipboard" type="button" onclick="copyCode(this)"><span class="copy-button-text">Copy</span></button></div><pre><code class="hljs language-bash">mount /dev/c0d1 /mnt
</code></pre></div>
<p>Pay attention to the error. If it says the device or address does not exist, try the next one, such as <code>c0d3</code>, until you find a disk that no longer reports that error. Under the assumptions above, exclude <code>c0d0</code> and <code>c0d2</code>; if <code>c0d1</code> doesn't report a "no such device or address" error, then <code>a.img</code> is that device.</p>
<p>In MINIX, partition it with <code>fdisk</code>:</p>
<div class="code-block-wrapper"><div class="code-block-header"><span class="code-block-lang">bash</span><button class="copy-button" data-copy-state="copy" aria-label="Copy code to clipboard" type="button" onclick="copyCode(this)"><span class="copy-button-text">Copy</span></button></div><pre><code class="hljs language-bash">fdisk /dev/c0d1
</code></pre></div>
<p>In fdisk, use the <code>c</code> command to change partition information, then use <code>w</code> to write it to the <code>a.img</code> image.</p>
<p>After partitioning <code>a.img</code>, format it with <code>mkfs</code>. <strong>Be sure to use the <code>ext2</code> file system here, because <code>ext2</code> is well supported by both MINIX and Linux.</strong> The command is:</p>
<div class="code-block-wrapper"><div class="code-block-header"><span class="code-block-lang">bash</span><button class="copy-button" data-copy-state="copy" aria-label="Copy code to clipboard" type="button" onclick="copyCode(this)"><span class="copy-button-text">Copy</span></button></div><pre><code class="hljs language-bash">/sbin/mkfs.ext2 /dev/c0d1
</code></pre></div>
<p>Now <code>c0d1</code> is a mountable device, and you can mount it:</p>
<div class="code-block-wrapper"><div class="code-block-header"><span class="code-block-lang">bash</span><button class="copy-button" data-copy-state="copy" aria-label="Copy code to clipboard" type="button" onclick="copyCode(this)"><span class="copy-button-text">Copy</span></button></div><pre><code class="hljs language-bash">mount /dev/c0d1 /mnt
</code></pre></div>
<p>After mounting, go to <code>/mnt</code> and copy all the files you need there. When done, unmount it and shut down the VM.</p>
<p>Back on Linux, <code>a.img</code> now contains the copied files. Just mount <code>a.img</code> as a device:</p>
<div class="code-block-wrapper"><div class="code-block-header"><span class="code-block-lang">bash</span><button class="copy-button" data-copy-state="copy" aria-label="Copy code to clipboard" type="button" onclick="copyCode(this)"><span class="copy-button-text">Copy</span></button></div><pre><code class="hljs language-bash"><span class="hljs-built_in">sudo</span> mount -t ext2 a.img /mnt
</code></pre></div>
<blockquote>
<p>Regular users need <code>sudo</code> to elevate privileges; root doesn't.</p>
</blockquote>
<p>Go into <code>/mnt</code> and check that all the files are there.</p>
<blockquote>
<p>This is a general way to copy files out of QEMU. The prerequisite is that the guest and host both support a common file system, which then serves as the transfer medium.</p>
