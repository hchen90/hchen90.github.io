16:T188c,<h2 id="what-are-fitting-problems">What Are Fitting Problems<a aria-hidden="true" tabindex="-1" href="#what-are-fitting-problems"><span class="anchor-link"> #</span></a></h2>
<p>Fitting problems boil down to how well a model learns the patterns in the data. A model that learns well is said to have a good fit; one that learns poorly falls into one of two categories: overfitting or underfitting.</p>
<p>Fitting means approximating the relationships in the data with a model function, and the degree of fit reflects how closely the model function matches the actual data.</p>
<h2 id="overfitting">Overfitting<a aria-hidden="true" tabindex="-1" href="#overfitting"><span class="anchor-link"> #</span></a></h2>
<p>Overfitting means the model performs very well on the training data but poorly on test data. The usual cause is fitting the training set too closely, to the point of learning its noise, which leads to large errors when generalizing to new data.</p>
<h3 id="an-overfitting-example">An Overfitting Example<a aria-hidden="true" tabindex="-1" href="#an-overfitting-example"><span class="anchor-link"> #</span></a></h3>
<p>Here is an example using a training case on BigML. The model predicts whether a hotel customer who makes a booking will later cancel it.</p>
<p>The dataset is shown below.</p>
<p><img src="/post/mltraningfittingissues/e1a6ccff4af1.png" alt="Overfitting training dataset"></p>
<p>The prediction target is the value of reservation_status.</p>
<p><img src="/post/mltraningfittingissues/a51ce4a9bfa4.png" alt="Prediction target"></p>
<p>With the dataset ready, we can start training. The model here is a decision tree. Below is the evaluation score from an 8:2 train/validation split.</p>
<p><img src="/post/mltraningfittingissues/7a15aed8baba.png" alt="Evaluation with full accuracy"></p>
<p>The prediction accuracy reaches an astonishing 100%, which is clearly implausible, so overfitting is likely: the model has absorbed noise from the dataset.</p>
<p>Now look at its metrics and curves.</p>
<p><img src="/post/mltraningfittingissues/3ba51051620d.png" alt="Evaluation metrics with full accuracy"></p>
<p>These are the evaluation metrics, and the accuracy here is only 42%, indicating that the dataset is flawed and the model cannot make useful predictions.</p>
<h3 id="fixing-overfitting">Fixing Overfitting<a aria-hidden="true" tabindex="-1" href="#fixing-overfitting"><span class="anchor-link"> #</span></a></h3>
<p>This case uses a decision tree, so open the tree and inspect its branches.</p>
<p><img src="/post/mltraningfittingissues/cef5f782439a.png" alt="Decision tree branches"></p>
<p>The problem is immediately visible in the labeled fields: reservation_status and is_canceled are both output labels, but training treated is_canceled as an input. As a result, the other fields didn't take part in the computation at all.</p>
<p>To fix this, remove is_canceled from the training fields in the dataset, retrain, and re-evaluate. The result is:</p>
<p><img src="/post/mltraningfittingissues/3da0847efbbb.png" alt="Evaluation after fix"></p>
<p>The accuracy now looks normal and fairly good. Let's check the evaluation metrics.</p>
<p><img src="/post/mltraningfittingissues/68a26e0c6e2d.png" alt="Evaluation metrics after fix"></p>
<p>The accuracy in the evaluation metrics now exceeds 80%, which is a very good result.</p>
<p>We can also look at the shape of the decision tree:</p>
<p><img src="/post/mltraningfittingissues/9f2736e50a05.png" alt="Decision tree after fix"></p>
<p>Everything looks good: the overfitting problem has been eliminated.</p>
<h2 id="underfitting">Underfitting<a aria-hidden="true" tabindex="-1" href="#underfitting"><span class="anchor-link"> #</span></a></h2>
<p>Underfitting means the model performs poorly on both the training and test sets, because the fit is too weak to capture the patterns in the data.</p>
<h3 id="an-underfitting-example">An Underfitting Example<a aria-hidden="true" tabindex="-1" href="#an-underfitting-example"><span class="anchor-link"> #</span></a></h3>
<p>Again using BigML, I found an underfitting dataset, built the dataset on BigML, and trained a model, still a decision tree.</p>
<p><img src="/post/mltraningfittingissues/efbad76148fd.png" alt="Underfitting training dataset"></p>
<p>The evaluation scores are shown below.</p>
<p><img src="/post/mltraningfittingissues/c0e5a232e33e.png" alt="Underfitting evaluation"></p>
<p>The accuracy doesn't look especially low, but the Phi coefficient is only 0.3, meaning predictions correlate very weakly with actual values. This model is also flawed and unfit for prediction.</p>
<blockquote>
<p>What the Phi coefficient means</p>
<p>The Phi coefficient measures the correlation between predictions and actual outcomes: +1 means perfect prediction, 0 means completely random, and -1 means completely inverted. It generally ranges from -1 to 1, and the closer to 1, the better.</p>
</blockquote>
<h3 id="fixing-underfitting">Fixing Underfitting<a aria-hidden="true" tabindex="-1" href="#fixing-underfitting"><span class="anchor-link"> #</span></a></h3>
<p>There are several common ways to address underfitting. The first is to add or remove features (add features to datasets with too few, remove them from datasets with too many), adjusting the feature count so the model can learn the patterns during training. The second is to try a different model, because different models suit different datasets. For example, if the data has simple linear relationships, linear models such as linear or logistic regression fit better; if there are many features with non-linear relationships, a decision tree is more appropriate. The third is to increase the sample size if there are too few samples, which also helps the model learn from the dataset.</p>
<h2 id="summary">Summary<a aria-hidden="true" tabindex="-1" href="#summary"><span class="anchor-link"> #</span></a></h2>
<p>In machine learning, both overfitting and underfitting can be spotted by training the model and evaluating the results. Overfitting is usually a labeling problem in the dataset and can be fixed with appropriate corrections.
