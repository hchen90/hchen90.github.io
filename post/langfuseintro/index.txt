15:T50c6,<p>LLM 应用上线后，开发者很快会意识到：一次用户请求往往要经过提示词组装、多轮模型调用、RAG 检索、工具调用和 Agent 决策等多个环节。出了问题时，只看到最终输出错误，却难以定位是哪一步偏离了预期。Langfuse 正是为解决这类「黑盒」问题而生的开源可观测性平台。</p>
<h2 id="什么是-langfuse">什么是 Langfuse<a aria-hidden="true" tabindex="-1" href="#什么是-langfuse"><span class="anchor-link"> #</span></a></h2>
<p><strong>Langfuse</strong> 是一个开源的 LLM 工程与 LLMOps 可观测性平台，专为大语言模型应用和 AI 智能体（Agents）的开发、监控、调试与优化而设计。它以 <strong>Tracing（追踪）</strong> 为核心，把单次请求内部的每一次模型调用、工具执行、检索结果和状态变化都记录成结构化的 Trace，让团队能够像排查传统微服务一样排查 LLM 链路。</p>
<p>与同样面向 LLM 可观测性的 <strong>LangSmith</strong> 相比，Langfuse 最大的区别在于<strong>开源与自托管</strong>。LangSmith 是 LangChain 团队提供的闭源 SaaS 服务，功能强大但超出免费额度后需要按量付费，且无法完整部署到私有环境中。Langfuse 则采用 <strong>MIT 协议</strong> 完全开源，代码公开可审计；你可以选择官方托管的 <strong>Langfuse Cloud</strong>，也可以免费在自己的服务器上私有化部署，数据主权和成本完全可控。</p>
<p>项目提供两种方式使用：</p>
<ul>
<li><strong>Langfuse Cloud</strong>：官方托管的 SaaS 版本，适合快速上手或小团队。</li>
<li><strong>Self-Hosted</strong>：通过 Docker Compose 或 Kubernetes 私有化部署，无需向 Langfuse 支付授权费用，数据完全留在自己的基础设施里。</li>
</ul>
<p>无论是直接调用 OpenAI / Anthropic / 本地模型，还是通过 LangChain、LlamaIndex、OpenTelemetry 等框架接入，Langfuse 都能以较低的侵入性捕获关键遥测数据。</p>
<h2 id="核心特性">核心特性<a aria-hidden="true" tabindex="-1" href="#核心特性"><span class="anchor-link"> #</span></a></h2>
<p>Langfuse 的功能围绕「可观测、可评估、可迭代」三条主线展开，主要模块如下。</p>
<h3 id="tracing追踪">Tracing（追踪）<a aria-hidden="true" tabindex="-1" href="#tracing追踪"><span class="anchor-link"> #</span></a></h3>
<p>Tracing 是 Langfuse 的底座。每个用户请求对应一条 <strong>Trace</strong>，内部按时间线拆成多个 <strong>Span</strong> 和 <strong>Generation</strong>：</p>
<ul>
<li><strong>Generation</strong>：记录一次 LLM 调用，包括输入提示词、模型参数、输出内容、Token 用量和延迟。</li>
<li><strong>Span</strong>：记录任意业务步骤，如 RAG 检索、工具调用、知识库查询等。</li>
<li><strong>Event</strong>：记录关键事件，如用户反馈、错误异常。</li>
</ul>
<p>通过嵌套结构，开发者可以清晰看到请求在各阶段的耗时、成本和中间状态，快速定位幻觉、超时或检索失败。</p>
<p><img src="/post/langfuseintro/ce00805a6ef8.png" alt="tracing"></p>
<h3 id="metrics指标">Metrics（指标）<a aria-hidden="true" tabindex="-1" href="#metrics指标"><span class="anchor-link"> #</span></a></h3>
<p>平台会自动聚合 Trace 中的数据，生成可观测指标：</p>
<ul>
<li>Token 消耗与预估成本</li>
<li>延迟分布（P50 / P95 / P99）</li>
<li>错误率与调用成功率</li>
<li>模型使用分布</li>
</ul>
<p>这些指标既可以在 Dashboard 中查看，也支持通过 API 导出到现有的 Prometheus / Grafana 或 BI 体系。</p>
<p><img src="/post/langfuseintro/4f687f15edd8.png" alt="metrics"></p>
<p><img src="/post/langfuseintro/60d120180cea.png" alt="metrics_p"></p>
<h3 id="evals评估">Evals（评估）<a aria-hidden="true" tabindex="-1" href="#evals评估"><span class="anchor-link"> #</span></a></h3>
<p>Langfuse 把评估分为两类：</p>
<ul>
<li><strong>在线评估（Online）</strong>：生产流量到达后，通过规则、LLM-as-a-judge 或自定义函数自动打分，并关联到具体 Trace。</li>
<li><strong>离线评估（Offline）</strong>：基于数据集批量运行评测，用于回归测试、A/B 对比和提示词版本对比。</li>
</ul>
<p>评估结果以 <strong>Score</strong> 形式挂在 Trace 或 Generation 上，方便团队量化模型表现并追踪趋势。</p>
<p><img src="/post/langfuseintro/09e328649a1f.png" alt="evals_1"></p>
<p><img src="/post/langfuseintro/a458f23e4ff4.png" alt="evals_2"></p>
<p><img src="/post/langfuseintro/e0de38f9497f.png" alt="evals_3"></p>
<h3 id="prompt-management提示词管理">Prompt Management（提示词管理）<a aria-hidden="true" tabindex="-1" href="#prompt-management提示词管理"><span class="anchor-link"> #</span></a></h3>
<p>Langfuse 提供版本化的提示词管理：</p>
<ul>
<li>在界面中创建、编辑和版本控制提示词模板。</li>
<li>在代码中通过 <code>prompt_name</code> 和 <code>version</code> 调用，避免提示词散落在各处。</li>
<li>提示词改动可直接关联到 Trace，便于观察版本变化对输出的影响。</li>
</ul>
<h3 id="datasets数据集">Datasets（数据集）<a aria-hidden="true" tabindex="-1" href="#datasets数据集"><span class="anchor-link"> #</span></a></h3>
<p>Datasets 用于构建测试集和基准：</p>
<ul>
<li>从生产 Trace 中一键挑选 bad case 加入数据集。</li>
<li>批量运行相同输入，对比不同模型或提示词版本的表现。</li>
<li>与 CI 结合，实现提示词或模型变更前的自动回归测试。</li>
</ul>
<p><img src="/post/langfuseintro/3a920a4b821c.png" alt="datasets"></p>
<h2 id="安装部署">安装部署<a aria-hidden="true" tabindex="-1" href="#安装部署"><span class="anchor-link"> #</span></a></h2>
<p>Langfuse 的私有化部署以 Docker 为主。以下介绍本地快速体验和生产部署的核心思路；具体镜像版本和完整变量列表建议以<a href="https://langfuse.com/docs/deployment/self-host">官方文档</a>为准。</p>
<h3 id="本地快速启动">本地快速启动<a aria-hidden="true" tabindex="-1" href="#本地快速启动"><span class="anchor-link"> #</span></a></h3>
<p>官方推荐用 Docker Compose 一键拉起。一个最小化的本地栈通常包含以下服务：</p>
<ul>
<li><code>langfuse-web</code>：Web 界面与 API 入口。</li>
<li><code>langfuse-worker</code>：后台任务处理（如批量写入、评估任务）。</li>
<li><code>postgres</code>：元数据与项目数据存储。</li>
<li><code>clickhouse</code>：Trace 与事件数据存储。</li>
<li><code>redis</code>：任务队列与缓存。</li>
<li><code>minio</code>：S3 兼容的对象存储（用于上传文件、图片等）。</li>
</ul>

<h3 id="生产部署注意事项">生产部署注意事项<a aria-hidden="true" tabindex="-1" href="#生产部署注意事项"><span class="anchor-link"> #</span></a></h3>
<p>从本地体验过渡到生产时，建议重点关注以下几点：</p>
<ul>
<li><strong>外部数据库与对象存储</strong>：使用托管的 PostgreSQL、Redis 和 S3 服务，避免把状态卷在容器内。</li>
<li><strong>持久化与备份</strong>：ClickHouse 和 PostgreSQL 数据需要定期备份，尤其是 Trace 数据增长较快。</li>
<li><strong>高可用</strong>：<code>langfuse-web</code> 和 <code>langfuse-worker</code> 可以水平扩展；数据库和对象存储本身需独立做高可用。</li>
<li><strong>安全</strong>：
<ul>
<li>所有加密密钥（<code>NEXTAUTH_SECRET</code>、<code>SALT</code>、<code>ENCRYPTION_KEY</code>）都应通过 Secrets 管理，避免写入 Git。</li>
<li>为 Web 服务配置 HTTPS 和合适的访问控制。</li>
</ul>
</li>
<li><strong>资源规划</strong>：Trace 数据量随流量线性增长，需根据保留策略规划 ClickHouse 与对象存储容量。</li>
</ul>
<p>如果团队没有运维 Kubernetes 的经验，Langfuse Cloud 是更省心的选择；它提供相同的功能，只是把基础设施托管给官方。</p>

<h2 id="总结">总结<a aria-hidden="true" tabindex="-1" href="#总结"><span class="anchor-link"> #</span></a></h2>
<h3 id="适用场景">适用场景<a aria-hidden="true" tabindex="-1" href="#适用场景"><span class="anchor-link"> #</span></a></h3>
<p>Langfuse 最适合以下几类 LLM 应用：</p>
<ul>
<li><strong>RAG 应用</strong>：需要追踪检索结果、重排序、上下文拼接与最终生成之间的关联。</li>
<li><strong>Agent 系统</strong>：Agent 会多次调用模型、工具或外部 API，Trace 能帮你看清每一步决策与状态。</li>
<li><strong>多模型策略</strong>：同时调用多个模型或做模型降级时，需要对比延迟、成本与输出质量。</li>
<li><strong>成本敏感业务</strong>：希望按用户、按会话追踪 Token 消耗，识别异常流量或高成本调用。</li>
<li><strong>持续迭代团队</strong>：需要把提示词版本、评估分数与线上反馈串起来，形成迭代闭环。</li>
</ul>
<h3 id="与同类工具的差异">与同类工具的差异<a aria-hidden="true" tabindex="-1" href="#与同类工具的差异"><span class="anchor-link"> #</span></a></h3>
<p>市面上类似的 LLM 可观测性工具不少，例如 LangSmith、Phoenix（Arize）、Weights &#x26; Biases 等。Langfuse 的主要差异在于：</p>
<ul>
<li><strong>开源且可私有化</strong>：MIT 协议，支持 Docker 和 Kubernetes 自托管，数据主权完全可控。</li>
<li><strong>以 Tracing 为核心</strong>：Trace 结构清晰，Generation、Span、Event 分层明确，便于下钻排查。</li>
<li><strong>功能一体化</strong>：观测（Tracing/Metrics）、评估（Evals）、提示词管理、数据集测试集中在同一平台，减少工具链割裂。</li>
<li><strong>框架无关</strong>：除了官方 SDK，也支持 OpenTelemetry、LangChain、LlamaIndex、Vercel AI SDK 等多种接入方式。</li>
</ul>
<h3 id="上手建议">上手建议<a aria-hidden="true" tabindex="-1" href="#上手建议"><span class="anchor-link"> #</span></a></h3>
<p>对于刚接触 Langfuse 的团队，建议按以下顺序推进：</p>
<ol>
<li><strong>先用 Cloud 验证</strong>：注册 Langfuse Cloud，花 30 分钟接入一个真实接口，确认 Trace 数据符合预期。</li>
<li><strong>覆盖关键路径</strong>：为生产环境的核心调用链路加上 SDK 或装饰器，先把「能看」的问题解决。</li>
<li><strong>补齐元数据</strong>：在 Trace 中携带 <code>user_id</code>、<code>session_id</code>、<code>metadata</code>，方便后续按用户或会话聚合。</li>
<li><strong>引入评估</strong>：从简单的规则打分或 LLM-as-a-judge 开始，逐步建立质量基线。</li>
<li><strong>管理提示词版本</strong>：把关键提示词迁到 Langfuse Prompt Management，关联 Trace 观察版本影响。</li>

</ol>
